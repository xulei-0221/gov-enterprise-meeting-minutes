# 政企会议纪要生成 Skill

> 一份面向**天禧 AI Pro 会议助手**及类似政企智能体的会议纪要生成规范，基于《党政机关公文格式》GB/T 9704-2012、《党政机关公文处理工作条例》以及真实公文范例制定，确保大模型每次输出的会议纪要在**格式、结构、语言风格**上完全一致，可直接交付党政机关与国有企业客户。

## 这是什么

把一次会议的**原始记录**（语音转写文本、要点列表、口述大意）转成**符合公文写作规范的会议纪要**——交付给大模型作为系统提示词/技能调用规范使用。

核心解决三件事：

1. **格式一致性**：每次输出的字段顺序、模块结构、标点用法完全锁死，无需人工再校格式
2. **公文体风格**：内置"准确、庄重、平实、简明"四原则与禁用词清单
3. **防止编造**：明确"宁缺勿编"，模型不会为补全格式而瞎填人名、数字、决议

## 快速上手

### 作为系统提示词使用

把 [政企会议纪要skill.md](政企会议纪要skill.md) 全文作为系统提示词注入，加一句路由：

> 当用户的请求涉及"整理会议纪要""生成会议纪要""会议总结成公文"等意图时，严格按以下 Skill 执行。

### 作为 Agent 工具调用

把 Skill 文档存为可被检索的技能文件，并暴露两个工具能力：

```text
meeting_minutes.generate(raw_material, version, with_header)
meeting_minutes.render_docx(template_path, fields, output_path)
```

### 端到端交互流程

模型在收到原始材料后会**强制走两轮必问**：

1. **开场必问**：正式版 vs 简版；正式版下是否套红头版头
2. **交付后必问**（仅红头版本）：是否基于红头模板生成 `.docx` 文件

完整流程见 [使用说明 §4](政企会议纪要生成skill-使用说明.md)。

## 重新生成 docx 模板

模板字体、字号、边距等参数都封装在 [build_template.py](build_template.py)，**不要直接在 Word 里改主模板**，要改请改脚本再重生成：

```bash
pip install python-docx
python3 build_template.py
```

模板核心参数（GB/T 9704-2012）：

| 项目 | 参数 |
|---|---|
| 纸张 | A4（210 × 297 mm） |
| 页边距 | 上 37 / 下 35 / 左 28 / 右 26 mm |
| 版心 | 156 × 225 mm（约 22 行 × 28 字） |
| 行距 | 固定 28 磅 |
| 标题字体 | 二号小标宋（红色 #C00000） |
| 正文字体 | 三号仿宋_GB2312 |
| 一级标题 | 三号黑体 |
| 二级标题 | 三号楷体_GB2312 |
| 反线 | 红色实线，宽度等同版心 |

## 字库依赖

模板使用 `仿宋_GB2312` `楷体_GB2312` `方正小标宋简体` 三套字库，Windows + Office 默认包含；Mac/Linux 部分环境可能缺失，建议：

1. 在客户机器上安装这三套字库（政企客户一般已统一装好）
2. 或在服务端把 docx 预渲染为 PDF 再交付，规避字体回退
